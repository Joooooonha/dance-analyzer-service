# 실제로 돌려서 확인한 버전
#
# 개발(macOS, 2026-09-09)
#   ultralytics 8.4.144 / torch 2.14.0 / numpy 2.2.6
#   opencv-python-headless 4.12.0.88 / dtaidistance 2.4.0
#
# 배포(맥미니, Fedora Asahi, 2026-09-09)
#   ultralytics 8.3.155 / torch 2.14.0 / numpy 2.2.6
#   **opencv 5.0.0.93** / dtaidistance 2.4.0
#
# ⚠️ 배포 환경은 OpenCV 5.0이다. 상한을 두지 않아 메이저 버전이 올라갔다.
#   회전 처리가 OpenCV 버전에 민감해서(engine/video_utils.py 참조) 확인했다:
#     CAP_PROP_ORIENTATION_AUTO 존재 ✅ / 끄기 성공(0.0) ✅
#     probe_video(user_dancer.MOV) → 1080x1920, rotation=90 ✅
#   6초 구간 분석도 정상(채점률 100%). **다만 4.x와의 수치 동일성은 확인하지 않았다.**
#   두 버전에서 같은 영상을 돌려 오차 통계를 비교하는 것이 남은 숙제다.
#
# ⚠️ numpy 버전 주의 (macOS 한정)
#   ultralytics는 macOS에서만 numpy 2.0~2.3.4를 배제한다:
#     numpy>=1.23.0;                    platform_system != "Darwin"
#     numpy!=2.0.*,!=2.1.*,!=2.2.*,...; platform_system == "Darwin"
#   반면 opencv-python-headless 4.12는 numpy<2.3.0을 요구해서 macOS에서는
#   두 제약이 겹치지 않는다. 실제로 numpy 2.2.6 + 위 조합으로 동작을 확인했으므로
#   `pip check` 경고는 무시해도 된다.
#   **배포 환경(Linux)에는 이 충돌이 없다** — ultralytics가 numpy>=1.23만 요구한다.
